# Примитивная база данных

Консольное приложение на Python, имитирующее работу с базой данных: создание и удаление
таблиц, CRUD-операции с записями, обработка ошибок, подтверждение опасных действий
и кэширование запросов. Структура таблиц хранится в `db_meta.json`, данные каждой
таблицы — в отдельном файле `data/<имя_таблицы>.json`.

Проект написан в процедурном стиле (без классов) на Python 3.12 и управляется через
[uv](https://docs.astral.sh/uv/).

## Установка

Нужен `uv` версии 0.5 или новее (`uv --version`).

```bash
git clone <адрес_репозитория>
cd <папка_репозитория>
make install        # или: uv sync
```

Установка пакета как отдельной консольной команды:

```bash
make build          # или: uv build
make package-install  # или: uv tool install dist/*.whl
database
```

## Запуск

```bash
make run            # или: uv run database
```

## Команды Makefile

| Команда | Действие |

## Управление таблицами

Поддерживаемые типы данных: `int`, `str`, `bool`. Столбец `ID:int` добавляется
в начало каждой таблицы автоматически.

| Команда | Описание |
|---|---|
| `create_table <имя_таблицы> <столбец1:тип> <столбец2:тип> ...` | создать таблицу |
| `list_tables` | показать список всех таблиц |
| `drop_table <имя_таблицы>` | удалить таблицу |
| `help` | показать справку |
| `exit` | выйти из программы |

Пример использования:

```text
>>> Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool
>>> Введите команду: list_tables
- users
>>> Введите команду: drop_table users
Таблица "users" успешно удалена.
```

## CRUD-операции

Данные каждой таблицы хранятся в отдельном файле `data/<имя_таблицы>.json`.
Строковые значения указываются в кавычках, логические — `true`/`false`.
Все поля, кроме `ID`, обязательны; `ID` генерируется автоматически.

| Команда | Описание |
|---|---|
| `insert into <имя_таблицы> values (<значение1>, <значение2>, ...)` | создать запись |
| `select from <имя_таблицы>` | прочитать все записи |
| `select from <имя_таблицы> where <столбец> = <значение>` | прочитать записи по условию |
| `update <имя_таблицы> set <столбец1> = <новое_значение1> where <столбец_условия> = <значение_условия>` | обновить запись |
| `delete from <имя_таблицы> where <столбец> = <значение>` | удалить запись |
| `info <имя_таблицы>` | вывести информацию о таблице |

Пример использования:

```text
>>> Введите команду: insert into users values ("Sergei", 28, true)
Запись с ID=1 успешно добавлена в таблицу "users".
>>> Введите команду: select from users where age = 28
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
+----+--------+-----+-----------+
>>> Введите команду: update users set age = 29 where name = "Sergei"
Запись с ID=1 в таблице "users" успешно обновлена.
>>> Введите команду: delete from users where ID = 1
Запись с ID=1 успешно удалена из таблицы "users".
>>> Введите команду: info users
Таблица: users
Столбцы: ID:int, name:str, age:int, is_active:bool
Количество записей: 0
```

## Обработка ошибок и подтверждение действий

Повторяющаяся логика вынесена в декораторы (`src/primitive_db/decorators.py`):

- `handle_db_errors` перехватывает `KeyError`, `ValueError`, `FileNotFoundError`
  и выводит понятное сообщение вместо трассировки. Программа продолжает работу.
- `confirm_action(action_name)` перед опасной операцией спрашивает подтверждение.
  Операция выполняется только при ответе `y`:

  ```text
  >>> Введите команду: drop_table users
  Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: n
  Операция отменена.
  ```

  Применяется к `drop_table` и `delete`.
- `log_time` замеряет время выполнения `insert` и `select`:
  `Функция select выполнилась за 0.001 секунд`.
- `create_cacher()` — замыкание с кэшем результатов. Повторный одинаковый `select`
  по неизменённым данным берётся из кэша.
